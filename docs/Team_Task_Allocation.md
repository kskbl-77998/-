### 1.2 与初版方案的差异（为什么调整）

初版按「示例工程的 6 个角色」压缩成 5 人，把界面与渲染拆给两个人。实际人员确定后做了两处调整：

| 调整 | 原因 | 影响 |
| :--- | :--- | :--- |
| **界面 + 渲染合并给聂莹莹** | 两者共用同一个 `Canvas`、同一套坐标与配色，分开做反而要反复对齐 | 她的工作量变成全组最重（12 人日），第 3 周起由马子尊接手数轴控件 |
| **文档与测试拆开** | 「测试」需要持续跑、持续报 Bug，跟「写文档」的节奏完全不同频 | 李昆鹏专注质量，韩依桐专注表达，两人互为备份 |

### 1.3 为什么这样分

**① 按「文件所有权」分，不按「界面区域」分。**
每人独占自己那几个文件，日常开发几乎不会同时改同一个文件，合并冲突自然就少。唯一被多人触碰的是 `src/ui/app.py`——聂莹莹主写，马子尊在集成时只往末尾加自己的 `import` 与数据接线，**冲突演练就安排在这里**（见 4.3）。

**② 五个角色刚好覆盖作业的四个评分维度。**

| 评分维度（占比） | 直接责任人 | 支撑责任人 |
| :--- | :--- | :--- |
| 文档规范 20% | 韩依桐 | 马子尊（README）、全员供稿 |
| 协作流程 30% | 马子尊 | 全员（各自分支与提交） |
| Vibe Coding 25% | 韩依桐 汇总 | 全员各交 3 条提示词记录 |
| 程序实现 25% | 张家昂 + 聂莹莹 | 李昆鹏（验证） |

**③ 每人都有一个「可以独立演示」的产物。**
张家昂交 `pytest` 全绿截图，聂莹莹交能点开的空壳 + 静态渲染图，李昆鹏交测试报告，韩依桐交过审文档。任何一个人这周没来，其余四人仍能推进。

**④ 工作量不完全平均，但关键路径有备份。**
聂莹莹 12 人日是全组最高，因为界面和渲染本就该一起做；对应的补偿是第 3 周起马子尊接手 `number_line.py`（数轴控件），并且韩依桐负责界面文案，减少她的返工。

### 2.2 张家昂　核心算法工程师

| 项 | 内容 |
| :--- | :--- |
| 定位 | 全组唯一「算错就全错」的位置，优先级最高 |
| 分支 | `feature/core-logic` |
| 依赖 | 无外部依赖（纯标准库）；被聂莹莹、李昆鹏、韩依桐依赖 |

**任务清单**

- [ ] `bits.py`：位宽常量、`int → list[int]`、`list[int] → int`、符号位判定、补位/截断
- [ ] `represent.py`：原码 / 反码 / 补码 / 移码互转，处理 `−0` 与 `−128` 两个特例
- [ ] `negate.py`：`negate(bits)` 返回结果 + 进位链 + 逐步 trace（供动画用）
- [ ] `adders.py`：`add(a, b)` 返回 `list[BitColumn]` 与最终进位 `C_n`
- [ ] `overflow.py`：三种判定方法，返回带一致性的 `OverflowReport`
- [ ] 编写「算法推导笔记」（`docs/algorithm_notes.md`），把公式与教材页码对应起来
- [ ] 与李昆鹏一起把 16 条用例矩阵转成 `pytest` 断言
- [ ] 随机对拍脚本：200 组随机 `(X, Y, op)` 与 Python 原生整数结果比对

**必须处理的四个坑**

1. `−2^(n−1)`（`1000…0`）**没有相反数**，求补后仍是自己，必须报「超出范围」而非静默返回；
2. `−128` **没有原码 / 反码**表示，四码表对应位置要显示「不可表示」；
3. `0` 的原码有 `+0/0000 0000` 与 `−0/1000 0000` 两种，补码唯一；
4. 减法要先转成 `[X]补 + [−Y]补`，`[−Y]补` 的符号位也参与取反加一，不能只对数值位取反。

**验收标准**

- `pytest tests/ -v` 全绿，核心层覆盖率 ≥ 90%；
- 用例矩阵 16 条全部通过；
- 随机对拍 200 组零差异；
- `grep -r "tkinter" src/core/` 无结果（证明零 UI 依赖）。

### 2.3 聂莹莹　界面与可视化渲染

| 项 | 内容 |
| :--- | :--- |
| 定位 | 决定「第一眼好不好看、点起来顺不顺手」，以及「进位看不看得见」 |
| 分支 | `feature/ui-layout`（第 1–3 周）→ 合并后切 `feature/canvas-render`（第 3–4 周） |
| 依赖 | 只依赖 `models.py` 的字段（可用 mock 数据先行开发） |

> **为什么分两条分支**：布局与渲染是两件事，分开做能让每次 PR 的改动量可控（≤ 300 行），Review 也更容易。先合并布局，再基于最新 `main` 做渲染。
>
> 📘 **详细操作手册见 [`UI_Branch_Guide.md`](UI_Branch_Guide.md)**：13 个可交付小任务、每个控件的代码片段、渲染硬指标、12 个常见坑，以及可直接运行的参考实现 [`docs/examples/canvas_playground.py`](examples/canvas_playground.py)。

**第一阶段：界面骨架（`feature/ui-layout`）**

- [ ] `theme.py`：配色常量、字体族与字号、DPI 缩放函数 `_font()`
- [ ] `app.py`：三栏 + 底栏布局，`pack(fill=BOTH, expand=True)` 保证可拉伸
- [ ] `app.py`：交互状态机（IDLE / READY / RUNNING / DONE / ERROR）
- [ ] `controls.py`：字长单选、X/Y 输入框、加减切换、生成/单步/自动/重置、调速滑块
- [ ] `step_panel.py`：日志列表 + 自动滚动到当前行
- [ ] 键盘快捷键：`←/→` 单步、`空格` 播放/暂停、`R` 重置
- [ ] 非法输入的即时反馈（输入框描红 + 状态栏提示）

**第二阶段：可视化渲染（`feature/canvas-render`）**

- [ ] `bit_grid.py`：一排位方块，等宽字体，符号位列红色描边
- [ ] `bit_grid.py`：列高亮（当前正在计算的那一列）
- [ ] `bit_grid.py`：进位弧形箭头 `create_line(smooth=True)`，标注 `C_i`
- [ ] `bit_grid.py`：视野外图元剔除（culling），16 位时不卡顿
- [ ] `bit_grid.py`：求补阶段的「取反」逐位翻转动画
- [ ] `number_line.py`：数轴 `[−2^(n−1), 2^(n−1)−1]` 与刻度（**第 3 周起马子尊接手**）
- [ ] `number_line.py`：结果红点，越界时跳到区间外并闪烁

**验收标准**

- 双击 `main.py` 能开窗，无控制台报错；
- 拉伸到 1024×768 与 1600×900，控件不重叠、不跑出边界；
- 用 mock `Scenario` 能完整走完「单步 10 次 → 自动播放 → 重置」；
- 8 位加法动画：进位箭头从 b0 依次点亮到 b7，方向正确（向左）；
- 连续播放 50 次不出现残影、图元泄漏（`canvas.find_all()` 数量稳定）。

**给你的提醒**

先用假数据把界面跑起来（自己编一个 `Scenario` 字典就行），不要等张家昂的算法。等他的真数据到位，你只需要换数据源，布局代码不用动。

## 四、协作机制

### 4.1 结对备份

| 结对 | 理由 | 备份内容 |
| :--- | :--- | :--- |
| 张家昂 ↔ 聂莹莹 | 算法输出直接喂给渲染，字段理解必须一致 | 互相能讲清 `BitColumn` 每个字段 |
| 马子尊 ↔ 李昆鹏 | 集成后立刻要回归测试 | 李昆鹏能跑通 `main.py` 并定位到出错模块 |
| 韩依桐 ↔ 全员 | 文档素材来自每个人 | 每人每周主动丢一条素材给她 |

**交接标准**：接手者能在 **1 小时内**让程序跑起来并定位到出问题的函数，才算备份有效。

### 4.2 每日同步（群消息模板）

```text
【今日完成】实现 negate() 的进位链，8 位 −5 已能出 trace
【今日卡点】−128 求补结果仍是自己，不知道界面该提示什么
【明日计划】补边界用例，找李昆鹏一起跑回归
```

只写三行，不写长文。卡点超过一天必须升级给马子尊。

### 4.3 冲突演练脚本（作业硬性要求）

**目标**：在 `src/ui/app.py` 的 `_init_window()` 上制造一次真实冲突，并留下记录。

**参与人**：聂莹莹（改窗口尺寸）↔ 马子尊（在同一函数加画布参数）

```bash
# 1) 两人各自基于最新 main 开分支
git switch main && git pull
git switch feature/ui-layout      # 聂莹莹
git switch feat/engine            # 马子尊

# 2) 聂莹莹：把窗口高度从 800 改为 840（给数轴留空间）
#    self.root.geometry("1280x800")  ->  ("1280x840")

# 3) 马子尊：在同一函数里加入画布尺寸参数（集成时渲染需要）
#    self.root.geometry("1280x800")
#    self.canvas_w, self.canvas_h = 700, 420

# 4) 聂莹莹先合并（PR #3 已合入 main）
# 5) 马子尊拉取最新 main，触发冲突
git fetch origin && git merge origin/main
#    Auto-merging src/ui/app.py
#    CONFLICT (content): Merge conflict in src/ui/app.py

# 6) 在 VS Code 中打开，看到
#    <<<<<<< HEAD
#        self.root.geometry("1280x840")
#    =======
#        self.root.geometry("1280x800")
#        self.canvas_w, self.canvas_h = 700, 420
#    >>>>>>> origin/main

# 7) 协商结果：保留 840 的新尺寸 + 新参数
#        self.root.geometry("1280x840")
#        self.canvas_w, self.canvas_h = 700, 420

# 8) 标记已解决并提交

git commit -m "fix(ui): 解决 main 与 feat/engine 在窗口初始化参数上的冲突"
```
