## 一、为什么补码能把减法变成加法

设字长为 `n`，模 `M = 2^n`。在模 `M` 意义下，`−y` 与 `M − y` 是同一个同余类：

```text
x − y  ≡  x + (M − y)   (mod M)
```

而计算机的加法器天然"丢弃"溢出位，等价于 `mod M` 运算。所以只要把 `y` 换成 `M − y`（即 `[−y]补`），加法器就能算减法。

**这就是"符号位可以无脑参与运算"的全部理由**：它不是一个额外规定，而是模运算的必然结果。

## 二、`[X]补 = ~[X] + 1` 的推导

对负数 `X = −|X|`：

```text
[X]补 = 2^n − |X|
      = (2^n − 1) − |X| + 1
      = ~|X| + 1                    （因为 n 位全 1 减去任意 n 位数 = 按位取反）
```

而 `|X|` 的 n 位表示恰好等于 `[X]原` 去掉符号位后的数值部分。于是：

```text
[X]补 = ~[X]原的数值位 + 1
```

再把"符号位为 1、数值位取反"合并，就得到教科书上的口诀：

> **符号位不变，数值位取反，末位加一。**

而"求补"（由 `[X]补` 得到 `[−X]补`）是对**整个机器数**（含符号位）取反加一，两者不要混。

## 三、三种溢出判定的等价性

### 3.1 单符号位：`V = C_n ⊕ C_(n−1)`

- 两个正数相加，若最高数值位向符号位产生进位（`C_(n−1)=1`）而符号位本身不进位（`C_n=0`），符号位被"写坏"成正 → 正溢。
- 两个负数相加，符号位必然产生进位（`C_n=1`），若最高数值位没进位（`C_(n−1)=0`），符号位被"写回"0 → 负溢。
- 两者同进同出（`C_n = C_(n−1)`）时，符号位保持不变，无溢出。

故 `V = C_n ⊕ C_(n−1)`。

### 3.2 双符号位（变形补码）

把符号位复制一份放在数值位前面，得到 `00`（正）或 `11`（负）。相加时两个符号位都参与运算，结果的高两位只有四种可能：

```text
 00 + 00 → 00   正常（正 + 正 = 正）
 00 + 00 → 01   正溢（正 + 正 = 负）
 11 + 11 → 11   正常（负 + 负 = 负，最高位进位丢弃）
 11 + 11 → 10   负溢（负 + 负 = 正，最高位进位丢弃）
```

判据：结果高两位 `01` → 正溢，`10` → 负溢，`00` / `11` → 正常。
它的好处是**溢出方向一眼可见**，代价是多占一位。

### 3.3 操作数符号法

同号相加才可能溢出，且溢出表现为"结果符号与操作数相反"。异号相加不可能溢出（和的绝对值一定不大于任一操作数的绝对值）。

这条判据不需要进位信息，但**减法必须先化加法**，否则会漏判——这也是它最容易出错的地方。

## 四、三个必须写进代码的边界

| 边界 | 数学事实 | 代码要求 |
| :--- | :--- | :--- |
| `X = −2^(n−1)` 求补 | `−X` 超出表示范围 | 返回 `None`，上层提示"无相反数" |
| `X = −2^(n−1)` 转原码 / 反码 | 原码需要 `2^(n−1)` 的绝对值，放不进 n−1 位数值位 | 返回 `None`，界面显示"不可表示" |
| `X = 0` | 原码有 `+0`/`−0` 两种，补码只有一种 | 反码转换时先判 `0` |
